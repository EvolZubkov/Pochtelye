# ADR-0001: Ограничения платформы skript.rt.ru

- **Статус:** Accepted
- **Дата:** 2026-10-21

## Контекст

Приложение размещается на платформе skript.rt.ru (Python Platform, OKD). Источник: статья
«Как прописать взаимодействие серверной автоматизации с Порталом» (опубликована 2026-07-16).

## Факты

- Приложение — «веб-скрипт»: контейнер создаётся на один запуск одного пользователя и
  открывается в соседней вкладке. Контейнер временный.
- В контейнер передаются переменные: `PY_PLATFORM_JWT`, `PY_PLATFORM_SEND_STATUS`,
  `PY_PLATFORM_UPLOAD_FILE`, `PY_PLATFORM_GET_FILES`, `PY_PLATFORM_DOWNLOAD_FILE`,
  `PY_PLATFORM_API_BASE`.
- JWT передаётся заголовком `jwt` (не `Authorization`), живёт 10 часов. Поля: `iss`, `sub`
  (uuid пользователя), `executionId`, `jti`, `sid`, `typ`, `azp`, `iat`, `exp`.
  Имени, почты и групп нет.
- Приложение обязано слать статусы в `POST /pods/status`: `CREATING`, `RUNNING`, `WORKING`,
  `FINISHED`, `ERROR`, `TERMINATING`. Без статуса скрипт не стартует; после `TERMINATING`
  статус отвергается.
- Файловое API (`/pods/storage/upload`, `/files`, `/download`) работает только с личными
  файлами запустившего пользователя. Общего хранилища нет.
- S3-бакет сервиса создан с квотами; секреты в окружение пока не прокидываются
  (задача в бэклоге платформы). Прямого доступа к S3 нет, только через CI/CD на GitFlame.
- Доступ к Exchange и SMTP relay из периметра платформы не проверен.

## Решение

1. Фоновые задачи (очередь рассылок, планировщик) не размещаются в контейнере скрипта.
2. Идентичность — `sub` из JWT; имя и почту хранит само приложение. Роли хранятся в
   собственной БД и привязаны к `sub`.
3. Хранилище данных скрыто за интерфейсом `Repository` (SQLite для разработки и тестов,
   PostgreSQL для прода). S3 и файловое API платформы — только для файлов.
4. Платформенный клиент (`PlatformClient`) имеет локальную заглушку, чтобы приложение
   запускалось и без платформы.

## Открытые вопросы (к платформенной команде)

1. Можно ли деплоить постоянный сервис (не скрипт) в OKD для очереди и планировщика?
2. Есть ли у платформы PostgreSQL для сервисов и кто владелец?
3. Когда в окружение попадут секреты для S3?
4. Есть ли API для получения имени и почты по `sub`?
5. Когда приходит `TERMINATING` при закрытии вкладки, есть ли таймаут простоя?
6. Как из контура платформы получить доступ к Exchange / SMTP relay?
7. Download: `POST /pods/storage/download` с uuid в теле или `GET /download/{uuid}`
   (статья противоречит сама себе)?
