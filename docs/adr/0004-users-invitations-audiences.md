# ADR-0004: Пользователи по приглашениям, аудитории, журнал отправок

- **Статус:** Accepted
- **Дата:** 2026-10-21

## Контекст

В JWT платформы только `sub` (ADR-0001): ни имени, ни почты. Нужна админ-панель, где
администратор заводит людей, назначает роли и функционал и следит за отправками
(кто, когда, сколько, кому).

## Решение

1. **Вход только по приглашению.** Админ создаёт пользователя по рабочей почте и получает
   одноразовый код (16 символов без похожих `0/O/1/I/L`, например `ABCD-EFGH-JKMN-PQRS`).
   Человек вводит код при первом входе, запись привязывается к его `sub`. Неизвестный `sub`
   без приглашения получает 403 `not_activated`. Администраторов-«затравку» задаёт
   `ADMIN_SUBS`.
2. **Код.** В БД только SHA-256 хэш, срок 14 дней, одноразовый; привязка выполняется одним
   условным `UPDATE` (гонка двух попыток невозможна). Неудачные попытки ограничены
   (5 за 15 минут на `sub`, не более 10 000 отслеживаемых ключей).
3. **Роль и аудитория.** Роль (`admin`, `editor`, `viewer`) определяет права в системе.
   Аудитория — профиль редактора из v2 (какие блоки доступны, их возможности, настройки по
   умолчанию, функции `bulk_mail`/`exchange_send`). Пользователь привязан к аудитории; без
   привязки действует аудитория по умолчанию. Неизвестные ключи профиля сохраняются.
4. **Журнал отправок** (`send_log`): отправитель (с копией почты), время, тема, получатели,
   статус, код ошибки. Отправка писем ещё не реализована; она будет вызывать
   `Repository.record_send`. Адреса получателей — PII: видны только администраторам,
   в логи не пишутся.
5. **Удаление мягкое.** Удаление пользователя освобождает `sub` и почту, поэтому человека
   можно пригласить заново; журнал хранит снимок почты.
6. **Режим по умолчанию — `prod`.** Вход без JWT (`ENV=dev`) включается только явно.

## Последствия

- Когда платформа начнёт отдавать почту, привязку можно сделать автоматической по email и
  оставить коды как запасной путь.
- Нельзя понизить или удалить себя; администратор из `ADMIN_SUBS` воссоздаётся при входе.
- Ограничитель попыток живёт в памяти процесса: при нескольких репликах нужен общий стор.
- Подпись JWT по-прежнему не проверяется (ADR-0001, вопрос 8): пока ключа нет, `sub`
  можно подделать, и защита приглашением держится на доверии к периметру платформы.
