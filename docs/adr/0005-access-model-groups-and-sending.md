# ADR-0005: Модель доступа (аудитории и группы), вход по login, схема отправки

- **Статус:** Accepted
- **Дата:** 2026-11-09

## Контекст

Каждый пользователь запускает свой временный контейнер на skript.rt.ru; общие данные
(пользователи, шаблоны, настройки аудиторий, очередь) должны жить вне контейнеров.
Платформа ответила на вопросы ADR-0001: в JWT есть `sub`, `name` (ФИО), `login` (почта),
`rights`; формат статуса `{"status", "errorDescription"}`; скачивание файла
`GET /pods/storage/download/{uuid}`; ключ подписи JWT будет передан отдельно, передача
секретов в окружение ожидается к 2026-11-20.

## Решение

### 1. Что кому видно и можно: аудитория + группа

- **Аудитория** задаёт вид и ограничения редактора (профиль v2: блоки, их возможности,
  отступы, цвета).
- **Группа** лежит внутри аудитории и уточняет: `features` (перекрывают функции профиля),
  `categories` (какие категории общих шаблонов видны; `null`: все), `limits` (лимиты на
  будущее, поле есть, проверок пока нет). Один человек состоит в одной группе.
- Эффективные настройки считает единственный модуль `access.py`; редактор, API шаблонов и
  в будущем API отправки берут их оттуда.
- Тема шаблона = его категория. Личные шаблоны видны владельцу всегда. Чужой общий шаблон
  вне видимых категорий отвечает 404, как несуществующий. Администратор ограничений не
  имеет. Общий шаблон без категории виден группам без ограничения и тем, у кого в списке
  категорий есть пустая строка («шаблоны без категории»). Если у пользователя назначена
  группа, а самой группы уже нет, общих шаблонов он не видит (запрет, а не «видно всё»).
- Аудитория пользователя в группе всегда равна аудитории группы: сервер подставляет её при
  назначении, расхождение отклоняется (`group_audience_mismatch`).
- Администратор глобален: настраивает аудитории, группы, пользователей.

### 2. Почтовые ящики — не наша сущность

Доступ к ящикам (свой, групповой, «от имени») выдаёт сервер Exchange. У пользователя в
приложении только его подключение (сервер, логин, пароль) и список адресов «от кого»,
которые он выбирает сам. Группа к ящикам отношения не имеет: Вася и Петя в одной группе
видят приложение одинаково, но отправляют из разных ящиков.

### 3. Вход по login

Админ заводит человека по рабочей почте. При первом заходе приложение сопоставляет `login`
из JWT и привязывает `sub` (условный `UPDATE` по ещё свободной записи). Только при
проверенной подписи (`JWT_PUBLIC_KEY`, асимметричные алгоритмы): без ключа любой мог бы
подделать `login` и занять чужую запись, поэтому без ключа остаются коды приглашений
(ADR-0004). Без `JWT_PUBLIC_KEY` приложение в проде не запускается, пока явно не задано
`ALLOW_UNSIGNED_JWT=true` (небезопасно: `sub` админа подделывается любым, кто достучится
до приложения мимо платформы; платформа обязана отбрасывать присланный клиентом заголовок
`jwt`). К уточнению у платформы: `login` всегда рабочая почта, есть ли `iss` и `aud`.
Неизвестная почта: отказ `not_activated`. **Будущее:** самоавторизация
(человек не заведён, но попал в контур): отдельное решение после получения ключа.

### 4. Отправка без открытого приложения

Планируемая схема (реализация следующим этапом):

- Очередь в общей БД (`send_jobs`, `send_job_recipients` со статусом по каждому адресату),
  воркер как отдельный процесс/контейнер. Платформа обещала проработать постоянный сервис;
  до ответа воркер запускается внутри приложения.
- Доступ к Exchange как в v2: NTLM, `exchangelib`, `DELEGATE`, `primary_smtp_address` =
  выбранный адрес «от кого». Kerberos воркеру недоступен (тикет у пользователя).
- Пароль Exchange шифруется Fernet; ключ (`CREDENTIALS_KEY`) из окружения и доступен только
  воркеру; UI-контейнер пароль принимает и шифрует, но прочитать не может.
- Правка очереди: пока рассылка не началась, её можно отменить или изменить целиком
  (адресаты, тема, время). После старта можно отменять и добавлять/удалять только
  неотправленных получателей.
- Журнал: кто, кому, когда, тема, шаблон, итог по каждому получателю. Текст письма не
  хранится (он в «Отправленных» Exchange).
- Метрики для платформы: аптайм агента очереди, размер очереди, число пользователей,
  число рассылок, уникальные получатели, число писем, плюс сигнал об отсутствии heartbeat.

## Последствия

- `users.group_id`, таблица `groups` (миграция 0004). Группу с пользователями и аудиторию с
  группами удалить нельзя.
- Серверная проверка контента шаблонов по профилю аудитории (цвета, отступы, блоки) пока
  не реализована: ограничения действуют только в редакторе. Это следующий этап.
- До получения ключа подписи JWT приложение нельзя выставлять мимо платформы.
- Метрики и воркер ждут решения платформы о постоянном сервисе и формате сбора метрик.
